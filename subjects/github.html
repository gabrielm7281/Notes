General Knowledge

Github is the central place for every programming project to originally start off in. It is very useful for viewing code and hosting websites, but it is a little limited in its function. The main place to code and get previews of your work is your IDE. Since Github cant run all kinds of languages, you need to have other ways to preview things and that is why you use an IDE to allow for these limitations. From the IDE, you can work on your project even without wifi if it is a local project. That means if it is downloaded and installed onto your device, you can run/edit the program anywhere you want. However you do need wifi to actually push the project onto Github, which is where it is publicly availible, and where you can put it onto a website. You can push (move from computer to Github), pull (from Github to IDE) and fork (copy someone elses project) into the IDE. You can push and pull from a central place and Github merges the two saves together once everything is loaded.

Basic Terminal Commands

The terminal has a lot of commands and ways to do things, but there are a few core ones that you should memorize to make navigating the IDE much easier. These are more of navigation aids that help you find files and work with the IDE.

    Up Arrow Shows previous command

    Ctrl C, D, X Cancels actions such as HTTP-Server

    Ctrl V Preview .md documents such as writeups and blogs.

    pwd Shows file path from where you are

    ls Lists all the files in the folder you are in

    http-server Makes a temporary website to preview code that you are working on

Basic Git Commands

Since the IDE works with Github, you need to use Git commands to "talk" with the cloud servers. These are different from the Terminal commands and are more about saving and moving your work rather than creating and editing files. These are the more basic, common commands you will use.

    git clone SSH Clones the repo into the IDE so you can work on it from there (Plug in SSH code into SSH for it to work)

    git add . Tells the IDE to "add" files to the staging ground. The dot can be replaced with a specific file but otherwise it will just add the entire folder

    git commit -m "message" Commit tells the IDE that the files are ready to be pushed to the Github servers. You need to attach a commit message, and it is good habit to give a quick sumamry of what is included in the commit

    git push Pushes the committed files into the Github Repo for public viewing.

    git status It shows what has been added and committed using yellow and green colors

Advanced Terminal Commands

These commands are more advanced and are more for creating and moving around files in your IDE. It covers all kinds of file types, and makes sub folders inside of parent folders.

    mkdir This makes a folder/directory.

    rmdir This removes a folder/directory

    rm This removes a file as long as it is empty

    rm -rf This can remove all of the content inside of a folder, unlike rm or rmdir

    mv This can both rename and move a folder or file. Writing the file name, and then a file path will move it, but writing the file name and another file name will rename it to the second file name.

Advanced Git Commands

There are several more commands that arent as important, but are still very useful to know just in case. These mostly cover going back to other versions of a file (seeing its history), and it is pretty important when working on large projects.

    git diff It shows what you have added or removed from the file

    git log Tracks and shows all of the commits you have made to the repo

    git revert SHA Reverts the file back to a previuos commit using the SHA code, which can be found in commit history on Github

    git revert HEAD Makes the file go back to the previous commit

    git restore file Resets a file back to its original commit

    git restore --staged "file" Takes back a file that has already been staged and committed
